# Wait, what?

The user didn't follow your last message. They may not be a software engineer, so the message probably assumed something they don't know, or used words they don't use.

Explain it again from the start, and keep it short:

1. **Where we are.** One or two sentences: what we're working on and what just happened.
2. **What you said, in plain words.** Short sentences, everyday words. Name things the way the user names them (the page, the agent, the email, the site, the button), not the file, function or tool. If a technical word can't be avoided, explain it in a few words the first time.
3. **Why it matters to them.** What changes for customers, for visitors, or for them.
4. **What you need from them, if anything.** One clear question or step. If nothing is needed, say so.

Use the project's own words for things. If the repo has a `GLOSSARY.md`, use its terms.

Don't repeat the earlier message in other words, and don't add new findings. If the confusion shows you made a mistake or skipped a step, say so plainly.
